### Provider terms and credential lifecycles

**OpenAI.** The Sign in with ChatGPT terms effective November 4 say “Do not impersonate OpenAI, another application or entity, or another open-source project.” The terms also require persistent token storage to be “local and under the user’s control”. For plan usage, requests must originate on the user's local runtime or a remote runtime the user alone controls. User authorization and app-specific use are required, and users must be able to use their plan in the app for free. A shared Betterlook backend with persistent token storage needs an approved design from OpenAI. The hosted identity-only flow uses authorization code with PKCE, state, nonce, and `openid profile email`. It returns an ID token for a Betterlook session and supplies no inference credential. Public website docs give no commercial plan-token lifecycle. [Sign in with ChatGPT terms §1 and §3.1](https://openai.com/policies/sign-in-with-chatgpt-terms/), [website integration](https://developers.openai.com/siwc/website), [client request](https://developers.openai.com/siwc/request-client-id)

The public OSS plan flow adds `offline_access resource.invoke chatgpt.tokens.use.direct`. Access tokens last one hour. Refresh tokens rotate with a fresh 30-day lifetime, and refreshes must be serialized per session. On sign-out revoke the refresh token at the discovery document's revocation endpoint and clear credentials. Users can disconnect in ChatGPT settings. The documented returning OSS flow uses an ID-token hint at the authorization endpoint, so confirm a supported returning flow that satisfies Betterlook's rule against any token in a URL. Inference uses eligible models on the public Responses API with `store: false` and `stream: true`. Check model availability and the request contract with AI-CORE if selected. [Registration](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [token reference](https://developers.openai.com/siwc/token-sharing-open-source/token-reference), [sessions and revocation](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions), [inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)

**Anthropic.** Claude Code's credential policy says “Anthropic does not permit third-party developers to offer Claude.ai login into their own applications”. It also forbids routing requests on behalf of users through consumer plan credentials and collecting or storing their Claude.ai session tokens. Claude Code's own sign-in and the compliant hosted-binary option leave the token with the official binary. Public docs describe its local credential storage and logout. Third-party consumer scopes, expiry, refresh, and revocation are therefore unavailable to Betterlook. [Authentication and credential use](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use), [Claude Code credential management](https://code.claude.com/docs/en/authentication#credential-management)

For Claude Platform linked billing, request `billing:attribution` and add `offline_access` only for renewal. Connection tokens have `workspace:inference` and last at most one hour. The rotating refresh token has an absolute limit of one year, reported in `refresh_token_expires_in`. Serialize refreshes and follow Anthropic's retry rules. Revoke by connection ID through the OAuth revoke endpoint, or unlink in Claude Console. Both the access credential and the connection ID must be available during the connection lifecycle. A shared operator also needs explicit billing attribution on model requests. [OAuth reference](https://platform.claude.com/docs/en/manage-claude/oauth-apps/oauth-reference), [linked billing](https://platform.claude.com/docs/en/manage-claude/oauth-apps/organization-billing-connections), [app review](https://platform.claude.com/docs/en/manage-claude/oauth-apps/app-review)

**Google.** The Google APIs terms say “Developer credentials (such as passwords, keys, and client IDs) are intended to be used by you and identify your API Client.” Antigravity's terms prohibit “Using third party software, tools, or services to access the Service”. Google moved individual Gemini CLI plans to Antigravity CLI on June 18, 2026. The Gemini CLI terms also prohibit third-party access to the backend with CLI OAuth. Consumer subscription scopes, expiry, and refresh are internal to those products. [Google APIs Terms §4(b)](https://developers.google.com/terms/), [Antigravity terms](https://antigravity.google/terms), [Gemini CLI terms](https://geminicli.com/docs/resources/tos-privacy/), [Gemini CLI migration](https://github.com/google-gemini/gemini-cli#readme)

For Google API OAuth, identity scopes are `openid` plus `email` or `profile` if needed. The Gemini development quickstart shows `https://www.googleapis.com/auth/cloud-platform` and `https://www.googleapis.com/auth/generative-language.retriever` in a model-listing example. Confirm the minimum scope for the selected inference method before requesting access. User access tokens last one hour. Request `access_type=offline` if renewal is necessary, use the token endpoint to refresh, and handle early invalidation and any time-based expiry. Revoke via `https://oauth2.googleapis.com/revoke` using a form body. Revocation can affect other grants for the same project, so use a dedicated project for this integration. [Gemini OAuth quickstart](https://ai.google.dev/gemini-api/docs/oauth), [web-server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [Google Cloud token lifetime](https://docs.cloud.google.com/docs/authentication/token-types)

**xAI.** Its consumer terms say “You may not share your account credentials or make your account available to anyone else”. xAI's endorsements show user consent and plan usage for the named apps. No public Betterlook-eligible scopes, token lifetime, refresh, or revocation contract surfaced. Ask xAI for those details and its hosted-use terms if selected. The team-key API supports disabling or deleting keys in xAI Console. [Consumer terms §2](https://x.ai/legal/terms-of-service), [approved Grok OAuth example](https://x.ai/news/grok-kilocode), [API key security](https://docs.x.ai/developers/faq/security)

### Desktop and hosted execution

Desktop tools can invoke an official CLI on the user's machine and let it handle browser sign-in and credential storage. Codex documents that flow and offers a separate integration with Codex app-server using approved Sign in with ChatGPT credentials. Claude Code handles the user's own subscription in its official binary, including under its explicit hosted exception. Grok Build documents headless and ACP integrations and accepts subscription sign-in in the official CLI. Antigravity restricts third-party use of its consumer service. A browser-only Betterlook has no local process to run a CLI. A local companion or user-controlled runtime would change the deployment and agent contract. A hosted subprocess still needs explicit provider support and an approved way to isolate the user's execution and session. [Codex authentication](https://learn.chatgpt.com/docs/auth), [Codex app-server](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server), [Claude Code hosted terms](https://code.claude.com/docs/en/legal-and-compliance#can-customers-offer-claude-code-in-their-products), [Grok Build](https://docs.x.ai/build/overview), [Antigravity terms](https://antigravity.google/terms)
